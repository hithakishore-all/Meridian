# Set up Snowflake

This puts Meridian's data in your Snowflake account and lets the app sign in with a key pair (no password). It takes about 15 minutes. A free trial account works.

You will run SQL in a Snowflake worksheet and a few commands in a terminal. Run every terminal command from the `meridian/app` folder.

## 1. Sign in and open a worksheet

Sign in to Snowflake, choose **Projects → Worksheets → + (SQL Worksheet)**. Set the role picker to **ACCOUNTADMIN**.

## 2. Create the database, roles and tables

Open each file from the `sql/` folder, paste it into the worksheet, and choose **Run All**, in this order:

1. `01_setup.sql`: warehouse `MERIDIAN_WH`, database `MERIDIAN`, schemas `CORE` and `OPS`, roles `MERIDIAN_ADMIN` and `MERIDIAN_APP`.
2. `02_tables.sql`: all tables.
3. `03_views.sql`: the governed view `CORE.V_AGENT_FACTS` and helpers.

Each file switches to the role it needs. They are safe to re-run, but `02_tables.sql` empties the tables, so run step 3 again afterwards.

## 3. Load the demo data

Run `sql/04_seed.sql`. It is generated by `data/generate_data.py` and empties each table before loading, so re-running it is safe. Check it worked:

```sql
SELECT COUNT(*) FROM MERIDIAN.CORE.LISTINGS;   -- 19
SELECT EVIDENCE_ID, IS_STALE FROM MERIDIAN.CORE.V_AGENT_FACTS WHERE PROMPT_ID = 'orbit-brief';
```

## 4. Create the key pair

The app signs in with a private key that never leaves your computer. In a terminal, from `meridian/app`:

```bash
mkdir -p .keys
openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out .keys/meridian_svc.p8 -nocrypt
openssl rsa -in .keys/meridian_svc.p8 -pubout -out .keys/meridian_svc.pub
chmod 600 .keys/meridian_svc.p8
```

`.keys/` is in `.gitignore`, so the key is never committed. Copy the public key body (one line, without the BEGIN and END lines) to your clipboard:

```bash
# macOS
grep -v "PUBLIC KEY" .keys/meridian_svc.pub | tr -d '\n' | pbcopy
# Linux with xclip
grep -v "PUBLIC KEY" .keys/meridian_svc.pub | tr -d '\n' | xclip -selection clipboard
```

## 5. Create the service user

Open `sql/06_service_user.sql`. Replace `PASTE_PUBLIC_KEY_BODY_HERE` with your clipboard (keep the quotes), then **Run All**. This creates `MERIDIAN_SVC` with `TYPE = SERVICE` (it cannot sign in with a password) and grants the app role only what it needs.

Optional: on an account with Cortex AI functions (not trial accounts), run `sql/05_agents.sql` and set `MODEL` to `cortex`:

```sql
UPDATE MERIDIAN.OPS.CONFIG SET CONFIG_VALUE = 'cortex' WHERE CONFIG_KEY = 'MODEL';
```

## 6. Point the app at your account

Find your account identifier in the worksheet:

```sql
SELECT CURRENT_ORGANIZATION_NAME() || '-' || CURRENT_ACCOUNT_NAME();
```

Then create the app's settings file and fill in that value:

```bash
cp .env.example .env
```

Open `.env` in a text editor and set `SNOWFLAKE_ACCOUNT=` to the identifier (for example `myorg-myaccount`). Leave the other Snowflake lines as they are unless you changed names.

## 7. Check and start

```bash
npm ci
npm run check     # lists anything still missing, with the step that fixes it
npm start         # http://127.0.0.1:3000
```

The console's banner shows **live mode**. Open the **Audit log** tab after a run, or query it directly:

```sql
SELECT * FROM MERIDIAN.OPS.AUDIT ORDER BY AT DESC;
```

## Reset the demo

Press **Reset demo** in the console, or run `sql/07_reset.sql`. To reload every table from scratch, run `sql/04_seed.sql`.

## Change the demo data

Edit `data/generate_data.py`, then from the `meridian` folder run `python3 data/generate_data.py`. It rewrites `data/seed/*.csv`, `sql/04_seed.sql` and `app/fixtures/snapshot.json` together, so offline and live mode stay in step. Re-run `04_seed.sql` in Snowflake.

## Remove everything

```sql
USE ROLE ACCOUNTADMIN;
DROP DATABASE IF EXISTS MERIDIAN;
DROP WAREHOUSE IF EXISTS MERIDIAN_WH;
DROP USER IF EXISTS MERIDIAN_SVC;
DROP ROLE IF EXISTS MERIDIAN_APP;
DROP ROLE IF EXISTS MERIDIAN_ADMIN;
```
